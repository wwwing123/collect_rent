# 空置月份同步设计（「同步数据」）

**日期**：2026-07-14  
**状态**：已确认，待实施

## 1. 背景

账单按「房间 + 月份」唯一存储，每个月份录入后生成一条 `bills` 记录，缺失月份即没有记录。水电为累积读数，账单用量 = 本月读数 − 最近一条更早记录的读数（云函数 `getPrevBill` / `upsertBill` 取的是「最近一条更早月份」，而非紧挨的上个月）。

部分房间存在空置期：没人租住、水电表没走，因此这些月份没有录入。由于「表没动」时读数不变，水电计算在事实上仍是正确的（差值天然落在恢复入住后的第一个月）。问题集中在展示层：历史表格跳月、趋势图月份轴断档、CSV 导出缺少这些月份的行。

此前历史页曾有「补录历史读数」入口，已在 2026-07-13 的设计中移除。本次需要一个新功能，把这些空置月份**显式补全为账单记录**，使数据完整、表格 / 图表 / CSV 自然连续。

## 2. 目标

1. 提供「同步数据」功能，一键补全空置月份的账单记录。
2. 空置记录内容确定：读数 = 上一条记录读数，水电费 / 租金 / 杂费 / 合计均为 0，并打 `vacancy: true` 标记。
3. 历史页「同步数据」按钮：仅同步当前房间，点击后弹确认提示。
4. 首页「同步数据」按钮：同步所有 `status:'active'` 房间，点击后弹确认提示，仅管理员可见。
5. 操作幂等：重复点击不会重复插入。
6. 表格中空置月用浅色背景 +「空置」标记与真实录入月区分。
7. 趋势图因数据补全面自然连续，不修改图表逻辑。

## 3. 不在范围内

- 不补「最近一条记录」之后的月份，只补「最早记录 ↔ 最近记录」之间的空缺。
- 不做专门的「删除空置记录」撤销入口；`vacancy` 标记保证记录可识别，将来可低成本追加撤销功能。
- 不修改 CSV 导出格式，空置月作为普通行输出（读数重复、费用为 0）。
- 不修改水电计算逻辑、账单保存流程、收据逻辑。
- 不改动房间数据模型；`bills` 仅新增可选字段 `vacancy`。
- 不做自动同步，仅由用户手动点击触发。
- 不改动首页本月账本的汇总逻辑。

## 4. 方案选择

采用「一键补全 + 空置标记」方案。

未采用的方案：

- **展示层占位（不写库）**：CSV 仍不完整，其他页面与数据库不一致，不满足「数据补全」诉求。
- **自动补全**：进入页面即隐式改库，行为不透明，存在误插风险。
- **不打标记的一键补全**：真实录入月与空置月在表格中无法区分，且不可逆。
- **线性插值估算**：空置期读数本就确定（表没动 = 上一条读数），无需估算，插值反而引入不真实数值。

## 5. 界面与交互设计

### 5.1 历史页「同步数据」按钮

- 位置：历史页底部 footer 区，与「导出 CSV」并排。
- 点击 → `wx.showModal` 确认：「将补全当前房间【房号】缺失的空置月份，是否继续？」
- 确定 → 显示 loading → 调用 `syncVacancyMonths({ roomId })` → 成功后 Toast 显示「已补全 N 条」并刷新表格与趋势图。
- 若无空缺，Toast「已是最新，无需补全」。
- 取消则不执行任何操作。

### 5.2 首页「同步数据」按钮

- 位置：首页顶部管理员区，与 ⚙ 设置入口同区。
- 仅 `isAdmin` 为真时显示。
- 点击 → `wx.showModal` 确认：「将补全全部 N 个房间缺失的空置月份，可能需要几秒，是否继续？」（N 为 active 房间数）。
- 确定 → 显示 loading → 调用 `syncVacancyMonths({})` → 成功后 Toast「已处理 X 间房，补全 N 条」（X 为遍历的 active 房间数，N 为实际新增条数）。
- 同步只补历史空缺，不影响本月账本数字，无需刷新首页汇总。

### 5.3 表格空置月样式

- 空置月所在行使用浅色背景（`#FAF6F0`），月份旁加「空置」小字标签。
- 该行租金 / 水 / 电 / 其他 / 合计均为 0。
- 真实录入月保持原有样式。

### 5.4 趋势图

不修改图表逻辑。补全后 `getHistory` 返回的记录天然包含空置月，x 轴每月都在、空置月水电用量为 0（读数等于前一条，差值为 0），线条连续不断，满足「连续好看」。

## 6. 组件与文件职责

### `cloudfunctions/rentApi/vacancy.js`（新增，纯函数）

- 导出 `computeVacancyBills(bills, roomId)`：输入按 `year_month` 升序的 bills 数组，输出待插入的空缺记录数组。
- 内部自带月份推进与比较的纯函数（与前端 `format.js` 同语义，但用 CommonJS，避免跨模块系统依赖）。
- 每条输出记录包含：`room_id`、`year_month`、`water_reading`、`elec_reading`（均取自前一条记录）、各项费用为 0、`vacancy: true`。
- 纯计算、无副作用，便于单测。

### `cloudfunctions/rentApi/index.js`

- 新增 handler `syncVacancyMonths`（`requireAuth` 包裹）。
- 参数：`roomId` 可选。传则同步单房间；不传则遍历所有 `status:'active'` 房间逐个同步。
- 单房间流程：取该房间全部 bills → 按 `year_month` 升序 → 调 `computeVacancyBills` → 对每条待插入记录检查 `(room_id, year_month)` 是否已存在，不存在才插入（幂等）→ 累计插入条数。
- 返回 `{ syncedRooms, inserted }`。
- `upsertBill` 调整：在更新已存在记录的分支中将 `vacancy` 置为 `false`，使手动编辑过的原空置月转回真实月，避免「标记空置但费用非 0」的矛盾。

### `cloudfunctions/rentApi/vacancy.test.js`（新增）

- 单测 `computeVacancyBills`：补缺数量、读数 = 前一条、各项为 0、`vacancy:true`、跨年空缺、边界（空数组 / 单条 / 全连续）。

### `miniprogram/pages/bill/history/index.js`

- 新增 `onSync`：确认弹窗 → `callRentApi('syncVacancyMonths', { roomId })` → 成功后 `refresh()`。
- `refresh` 中 `history` 的 map 增加 `vacancy: !!b.vacancy`，供模板判断行样式。
- `_setLatestStats`、`updateChart` 逻辑不变（空置月被自然包含并正确处理）。

### `miniprogram/pages/bill/history/index.wxml`

- footer 区新增「同步数据」按钮，与「导出 CSV」并排。
- 表格行根据 `item.vacancy` 追加空置样式类，月份列追加「空置」标签。

### `miniprogram/pages/bill/history/index.wxss`

- 新增 `.sync-btn` 按钮样式。
- 新增空置行样式（如 `.tr-vacancy`）与「空置」标签样式。

### `miniprogram/pages/index/index.js`

- 新增 `onSync`：确认弹窗（含 active 房间数）→ `callRentApi('syncVacancyMonths', {})` → Toast。
- 复用 `data.isAdmin`，无需新增权限字段。

### `miniprogram/pages/index/index.wxml`

- greeting 管理员区（与 ⚙ 同区）新增「同步数据」按钮，受 `isAdmin` 控制。

### `miniprogram/pages/index/index.wxss`

- 新增首页同步按钮样式，与现有顶部入口视觉协调。

## 7. 数据流

**单房间同步**：

1. 用户在历史页点击「同步数据」→ 确认弹窗 → 确定。
2. 前端 `callRentApi('syncVacancyMonths', { roomId })`。
3. 云函数取该房间全部 bills，按 `year_month` 升序。
4. 调 `computeVacancyBills(bills, roomId)` 得到待插入空缺记录。
5. 逐条检查目标 `(room_id, year_month)` 是否已存在，不存在才插入。
6. 返回 `{ syncedRooms: 1, inserted: N }`。
7. 前端 Toast + `refresh()`，重新 `getHistory` 后表格与图表含空置月、自然连续。

**全房间同步**：

1. 用户在首页点击「同步数据」→ 确认弹窗 → 确定。
2. 前端 `callRentApi('syncVacancyMonths', {})`。
3. 云函数取所有 `status:'active'` 房间，对每个房间重复步骤 3–5。
4. 累加各房间插入数，返回 `{ syncedRooms: X, inserted: N }`；`syncedRooms` 为遍历处理的 active 房间数，`inserted` 为实际新增的空置记录总条数（部分房间可能无空缺、贡献为 0）。
5. 前端 Toast。

## 8. 边界与错误处理

- **房间无任何记录**：`computeVacancyBills` 返回空（无「前一条」可参照），跳过。
- **单条记录 / 全连续**：返回空，不插入。
- **幂等**：插入前检查 `(room_id, year_month)` 是否已存在（含已补的空置记录），已存在则跳过，重复点击安全。
- **跨年**：月份推进用专用函数，`2025-12` → `2026-01` 正确。
- **范围**：只补「最早记录 ↔ 最近记录」之间；最早之前、最近之后（含本月若未被录入）一律不补，避免误伤尚未录入的真实月。
- **读数容错**：取前一条读数时用 `?? 0` 兜底，与现有图表逻辑一致。
- **全房间批量**：房间数少（个位数）；注意云函数超时，必要时在云函数配置中调高超时上限。
- **字段兼容**：真实录入记录不带 `vacancy`（视为 false），空置记录为 `true`；现有读取均不依赖该字段，无回归。
- **空置月被手动编辑**：用户进入数据录入页修改一条已补全的空置月并保存后，`upsertBill` 将其 `vacancy` 置为 `false`，转回真实月，避免「标记为空置但费用非 0」的视觉矛盾。
- **失败处理**：同步过程出错时 Toast「同步失败」，不写入半成品数据。

## 9. 验收标准

1. 历史页 footer 出现「同步数据」按钮，与「导出 CSV」并排。
2. 点击历史页「同步数据」弹出确认弹窗，文案包含当前房号。
3. 确认后补全当前房间空置月份，Toast 显示补全条数，表格与趋势图变连续。
4. 首页顶部管理员区出现「同步数据」按钮，非管理员不可见。
5. 点击首页「同步数据」弹出确认弹窗，文案包含房间数。
6. 确认后补全所有 active 房间，Toast 显示间数与条数。
7. 重复点击「同步数据」不产生重复记录（幂等）。
8. 表格中空置月显示浅色背景 +「空置」标记，数字为 0，与真实月视觉区分。
9. 趋势图在补全后月份轴连续、空置月用量为 0。
10. 空置记录读数 = 上一条真实记录读数，水电费 / 租金 / 合计均为 0，`vacancy` 为 `true`。
11. 跨年空缺（如 `2025-12` → `2026-02`）能正确补出 `2026-01`。
12. 最近记录之后的月份不被自动补全。
13. 现有账单计算、保存、收据、CSV 导出功能不受影响。

## 10. 验证方式

- 运行 `cloudfunctions/rentApi/vacancy.test.js` 单测，覆盖算法、幂等、跨年与边界。
- 运行前端现有单测（`billing` / `format` 等），确认无回归。
- 在微信开发者工具中构造一个含空缺月份的房间，分别从历史页与首页触发同步，逐项验证验收标准。
- 连续点击两次「同步数据」，确认记录数不变（幂等）。
- 导出 CSV，确认空置月作为普通行出现（读数重复、费用为 0）。
