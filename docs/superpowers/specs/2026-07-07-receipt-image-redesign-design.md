# 收据导出图片格式重设计

**日期**: 2026-07-07
**状态**: 待评审
**参考图片**: 根目录 `shouju.png`

## 背景

当前 `/miniprogram/pages/receipt/preview` 页基于 Canvas 2D 渲染收据并支持导出 PNG。视觉上与房东长期使用的纸质收据格式有差距：

- 列数与纸质收据不一致（缺"实用"列）
- 行项目结构与现有账目对不上（多了"垃圾费"/"网络费"，缺"电梯费"/"其他"）
- 字体使用 `sans-serif` 默认字体，缺少正式感
- 背景色与纸质收据的粉色不符
- 合计行布局与纸质版不符

房东提供了纸质收据的扫描图（`shouju.png`）作为视觉参考。本设计目标是把现有 Canvas 渲染的收据改造成与参考图视觉一致的版本。

## 范围

**包含**
- 重写 `miniprogram/utils/receipt.js` 里的 `drawReceipt` 及其辅助函数
- 更新 `miniprogram/utils/receipt.test.js` 以覆盖新结构
- 调整 `miniprogram/pages/receipt/preview/index.js` 中的画布尺寸常量（如果需要）

**不包含**
- 不修改账单数据模型（不新增"电梯费"/"其他"/"备注"/"综合费用"等字段）
- 不修改云函数 `rentApi`
- 不修改数据库 schema
- 不修改房间编辑页和账单编辑页
- 不实现云端图片生成

## 设计决策

### 数据映射（无模型扩展）

纸质收据中的"电梯费"、"其他"行不引入新字段，而是用现有字段映射：

| 收据行 | 项目标签 | 数据源 |
|--------|----------|--------|
| 水费（吨） | 来自 `bill.water_reading` / `bill.water_fee` |
| 电费（度） | 来自 `bill.elec_reading` / `bill.elec_fee` |
| 租 金（元） | 来自 `bill.rent` |
| 垃圾费（元）| 来自 `room.garbage_fee`（替代"电梯费"位置） |
| 网络费（元）| 来自 `room.internet_fee`（替代"其他"位置） |

参考图中的"综合费用（度）"行整行去掉。

### 表格结构

7 列 × 6 行（含表头与合计行）：

| 列序 | 列名 | 对齐 | 备注 |
|------|------|------|------|
| 1 | 项　目 | 左 | |
| 2 | 上　月 | 居中 | |
| 3 | 本　月 | 居中 | |
| 4 | 实　用 | 居中 | = 本月 − 上月（水/电行） |
| 5 | 单　价 | 居中 | |
| 6 | 金额小计（元） | 右 | |
| 7 | 备　注 | 左 | 整列保留为空 |

行结构：

1. **表头**（粗体）
2. **水费（吨）**：上月读数、本月读数、实用、单价、金额小计
3. **电费（度）**：同上
4. **租 金（元）**：项目 + 合并单元格写"YYYY年M月份房租" + 金额小计列填 1400
5. **垃圾费+网络费（拆分行）**：左右两半 + 中间竖线分隔
   - 左半（cols 1-2）：垃圾费（元）label + 15
   - 中间（col 3）：空
   - 右半（cols 4-5）：网络费（元）label + 50
   - 金额小计列（col 6）：垃圾费 + 网络费之和（= 65）
   - 备注列（col 7）：空
   - 中间竖线位置：col 3 与 col 4 之间（即 `COL_X[3]` 这条线，整列贯穿该行）
6. **合计**：左半文字"合计人民币（大写）：贰仟零叁拾柒.伍圆整"跨多列，金额小计列写"¥2037.5"加粗

### 签名行

- "开票人：" 后面画下划线，不写字
- "收款人：" 后面画下划线，不写字
- 不绘制参考图中"Lucky"手写体（保持通用模板）

### 右侧竖排文字

保留 `存根(白)` / `客户(红)` / 第三行空位的竖排文字结构。颜色用 `#222`，字号 20px。

## 实现方式

**行驱动 + 单元格对象（推荐）**

`drawTable` 改为迭代行 → 迭代单元格。每个单元格定义为 `{ text, align, span, bold, isDivider }`：

- `text`：要绘制的字符串
- `align`：`'left' | 'center' | 'right'`
- `span`：跨越多少列（默认 1，租金行的描述文本 span = 4）
- `bold`：是否加粗
- `isDivider`：是否画竖线分隔（拆分行用）

这样能：
- 自然处理"租金"行的合并单元格
- 自然处理"垃圾费+网络费"拆分行
- 单元格位置自动按列宽计算，无需为每个元素硬编码坐标

`drawTableGrid` 仍然按 7 列画外框与行分隔线，但在拆分行额外画一道中间竖线。

## 风险与边界

- **首月无 `prevBill`**：`water_usage` / `elec_usage` 为 0，"实用"列显示 `0`（与现有行为一致）
- **垃圾费/网络费为 0**：金额小计列显示 `0.00`
- **房间名为空**（`room.code === '旧屋'`）：`userName` 用 `getReceiptUserName` 的旧规则
- **金额小数位**：金额小计列保持两位小数（`formatAmount` → `toFixed(2)`）
- **中文大写**：复用现有 `formatCNY` 函数
- **金额溢出**：单元格宽度固定，超长金额会被截断（与现有行为一致）
- **画布缩放**：`pixelRatio` 缩放保持不变（仅 W/H 数值改动）

## 验收标准

- 生成的 PNG 与 `shouju.png` 在结构上一致：列数、行数、合并单元格位置、颜色、字体
- 现有测试用例全部通过
- 新增的"实用"列、`垃圾费+网络费`拆分行、`合计人民币（大写）`布局均与本设计一致
- 不影响"保存到相册"与"分享"两条已有路径
